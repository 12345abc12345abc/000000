# IEG NEWS 프로젝트 규칙

- 언론 보도 목록은 **발행일 내림차순**(최신이 위)으로 배열한다.
  같은 날짜 안에서는 **메이저 언론사 순**(인지도 높은 매체 우선)을 적용한다.
  기준 순서 예: 매일경제 → 전자신문 → 연합뉴스 → 아시아경제 → 폴리뉴스 → 파이낸스투데이 →
  데일리경제 → 내외경제TV → 공감신문 → ABC뉴스 → 피앤피뉴스.
  실제 전체 순서는 `IEG NEWS.dc.html`의 `RANK` 배열이 기준이며, 매체를 추가할 때는
  기존 매체의 상대 순서를 바꾸지 말고 사이에 끼워 넣는다. `RANK`에 없는 매체는 맨 뒤로 간다.
- 기사 날짜는 `d`에 `'YYYY-MM-DD'`로 적는다. 기사 페이지의 `article:published_time` 등
  메타 태그에서 확인한 값을 쓴다.
- 화면은 세 개이며 주소의 #로 나뉜다(브라우저 뒤로 가기·주소 공유가 된다).
  - **홈**(`#/`): **PC(1024px 이상)에서는 왼쪽 소식지 패널, 오른쪽 언론 보도 패널**이 같은 높이로 나란히 놓이고
    **스크롤 없이 한 화면에 딱 찬다**(사용자 요청). 면(`.ieg-home-tile`)이 머리 막대(80px + 테두리 1px) 아래 남은 높이를
    정확히 채우고 두 패널이 그 높이로 늘어난다. 지면 높이 `--nl-h`는 화면 높이에서 고정 부분을 뺀 값이다.
    홈일 때 JS가 `html.ieg-onepage`를 달아 스크롤 막대 자리를 두지 않는다(넘칠 때만 막대가 생긴다).
    높이 720px 미만은 머리기사 사진 3:1, 660px 미만은 카드 줄을 빼고 머리기사·더보기만 둔다(겹치지 않게). 왼쪽 칸은 지면 폭만큼(최대 절반), 오른쪽은 나머지. 두 패널의 제목·더보기 높이를 맞춘다.
    - **두 패널은 색·모양이 같다**(흰 면, 둥근 18px, 머리카락 테두리, 제목 굵기 700 + 아래 머리카락 선, 빨강 더보기).
      패널마다 색을 다르게 하지 않는다(짙은 소식지 패널은 써 보고 뺐다).
    - 소식지 패널: 최신 호 지면이 사진처럼 한 면씩 놓인다(지면 높이는 화면 높이에 맞춤, `--nl-h`. 뒷장이 비어져 나오는 만큼 줄인다).
    - 언론 보도 패널: **가장 최신 기사 하나만 위에 크게**(16:9 사진 + 큰 제목, `.ieg-lead`), 나머지는 **모두 같은 모양의 카드**
      (사진 · 날짜와 매체 · 제목, `.ieg-story`)를 넓으면 한 줄에 셋, 휴대폰은 둘씩 놓는다. 사진이 있는 최근 기사 7건(1 + 6).
      화면 높이 1000px 미만이면 사진을 납작하게·간격을 좁게 해서 카드 두 줄을 넣고, 880px 미만이면 카드 한 줄(3건)만 둔다.
      홈 메인에는 '같은 내용이 여러 매체에…' 안내 문구를 두지 않는다(언론 보도 페이지에만 둔다).
      **두 패널 맞추기(PC)**: 카드 줄들이 남는 높이를 나눠 갖고 카드 사진이 그만큼 커진다(16:9 ~ 4:3, 그 이상은 늘리지 않는다).
      언론 보도 패널은 `contain: size`로 자기 내용으로 줄 높이를 키우지 않고 소식지 패널 높이를 따른다(안쪽 상자 `min-height: 0`).
      제목·머리기사·더보기는 줄지 않고 카드 줄만 줄어든다. 그래서 두 패널의 더보기 버튼이 같은 선에 온다.
      카드가 한 줄일 때(높이 940px 미만)는 남는 높이를 카드 위아래에 나누고, 사진은 2.2:1 ~ 4:3 사이.
      높이 820px 미만은 머리기사 사진 12:5, 간격을 조금 좁힌다. 한 줄 안의 카드는 subgrid로
      사진·날짜·제목 칸을 같이 써서 같은 선에서 시작한다.
      한국어 제목은 낱말 중간에서 끊지 않는다(`word-break: keep-all`).
    - 좁은 화면에서는 두 패널이 위아래로 쌓인다.
  - **소식지 페이지**(`#/newsletter`): 모든 호를 최신 호부터. 흰 패널(`.ieg-page-panel`) 안에 둔다.
  - **언론 보도 페이지**(`#/press`, `#/press/2` …): 전체 기사를 날짜순으로 `PER_PAGE`(20)건씩, 아래에 페이지 번호. 흰 패널 안에 한 칼럼.
  - 맨 위 머리 막대(`.ieg-nav`: 제호 + 두 페이지 바로가기)는 늘 붙어 있다.
    제호는 홈으로, 바로가기는 각 페이지로 간다. 지금 페이지의 바로가기는 짙은 알약으로 채운다.
    페이지를 바꾸면 맨 위부터 보여준다.
  - **하단 꼬리말(로고 바)은 어느 화면에도 두지 않는다.** 제호(`.ieg-mark`: IEG 빨강 #FF0000 + NEWS #333333)는 머리 막대에만 있다.
    내용이 짧아도 면이 화면 아래까지 차게 한다(`.ieg-home-tile`, `.ieg-page`의 `min-height`).
- 소식지 지면은 **크게** 보인다.
  홈에는 최신 호만 왼쪽 칸에 화면 높이에 맞춰 **한 번에 한 면**을 크게 놓는다(사용자 요청, 2026-10-15).
  **두 장 이상인 호는 넘겨 볼 수 있고, 미리보기에서도 뒷장이 있는 느낌**이 나야 한다: 다음 장이 앞장 뒤로 오른쪽 아래에
  살짝(12px, 세 장 이상이면 두 겹) 비어져 나온다(`.ieg-stack`, 모든 면을 한 칸에 겹쳐 놓는다). 양옆 원형 화살표(`.ieg-flip`,
  마우스는 지면에 올렸을 때, 터치 화면은 늘 보임)나 좌우로 밀어서 넘긴다. 넘기면 앞장이 왼쪽으로 빠졌다가 뒤로 들어가고
  뒷장이 앞으로 나온다(이전 면은 거꾸로). 앞장을 누르면 확대 보기, 비어져 나온 뒷장을 누르면 그 장으로 넘긴다.
  면 수 표시(1/2 같은 숫자)는 넣지 않는다. 한 장짜리 호는 화살표·뒷장 없이 한 장만. `더보기`는 소식지만 있는 페이지로 넘어간다.
  **소식지 페이지는 장수와 상관없이 한 줄로 쭉**(한 장씩 위아래, 최대 720px) 내려가며 본다.
  지면 한 장이 버튼 하나라 누르면 확대 보기에서 더 크게 읽는다.
  확대 보기는 어느 화면에서 열든 전체 면이 이어지고 끝에서 처음으로 순환한다.
- 지면에 요약·캡션·면 수 같은 텍스트를 붙이지 않는다. 호 표시만 붙인다.
  호 표시는 신문 날짜 줄처럼: 양옆으로 가는 회색 선이 뻗고 가운데에 `2026. 09`를 연·월 같은 크기(18px, 600)로.
  앞에 점을 찍지 않고, 월만 따로 크게 강조하지 않는다.
- 부모 hover로 자식을 움직이는 효과는 인라인 스타일로 불가능하므로 `<helmet>`의 `<style>`에
  클래스로 정의한다. 색은 `:root`의 CSS 변수(`--red`, `--ink`, `--parch` 등)를 쓴다.
- 소식지는 `ISSUES` 배열에 `{ issue, pages: [{ src }] }`로 넣는다.
  `issue`(예: `'2026. 09'`)는 그 호의 지면 위에 그대로 나온다.
  새 호는 배열 맨 앞에 넣고, 이미지는 `0/uploads/`에 추가하되 기존 파일명은 건드리지 않는다
  (순서는 파일명이 아니라 배열이 정한다).
- 언론 보도는 연도 탭이나 월 그룹 없이 날짜순이며, 모든 줄에 발행일을 표시한다.
- 홈 기사 사진이 깨지면 다음 사진 기사가 올라온다. 정렬·페이지 수는 `ARTICLES`에서 자동 계산되므로 기사만 추가하면 된다.
- 본문 폭은 1240px(`.ieg-in`)이다. 화면 전체 폭으로 늘이는 것은 써 보고 어색해서 되돌렸다.
- **내용을 가리거나 자르지 않는다**: 기사 제목에 말줄임(line-clamp, `…`)을 쓰지 않고 전부 보인다.
  사진을 칸에 맞춰 크게 늘여 내용이 잘리게 하지 않는다.
- **언론 보도 페이지(상세 페이지)는 한 줄**(한 칼럼)로 쭉 내려간다. 여러 칼럼으로 나누지 않는다.
- 발행일이 확인되지 않으면 `d`에 `'2024-05'`(일 미상) 또는 `'2017'`(월까지 미상)처럼 아는 만큼만 적는다.
  짧은 값은 내림차순에서 해당 기간 맨 뒤로 정렬된다.
- 기사 사진은 `img`에 원문 `og:image` 주소를 넣는다(핫링크). 매체가 기사마다 같은 로고를
  반환하면 넣지 않는다(예: `facebook_mknews.jpg`, `facebook_thumb_hankyung.jpg`, 경기도 `news_bi_og.png`).
- 사진이 없는 기사는 **썸네일 칸을 두지 않고** 글만 보인다. 빈 칸이나 빗금 자리를 넣지 않는다.
  사진이 깨지거나 40×30px보다 작은 그림이 오면 화면에서도 그 칸을 빼고 글만 남긴다(`brokenImg`).
  이 감지는 window의 capture 단계 load·error 리스너로 한다. 템플릿에 `onError`·`onLoad` 같은 이벤트 속성을
  쓰지 않는다. `<x-dc>` 원본 HTML이 먼저 실제 DOM으로 깔리면서 그 속성이 브라우저 기본 핸들러로 실행돼
  `item is not defined` 오류가 난다(`onClick`은 누르기 전엔 실행되지 않아 괜찮다).
- 기사 제목은 원문 전체 제목을 그대로 쓴다.
- **같은 내용의 기사가 여러 매체에 실린 경우 메이저 언론사 것만 남기고 마이너 매체 것은 뺀다.**
  제목이나 취재 각도가 조금이라도 다르면 남긴다(별도 인터뷰·르포·기획, 다른 사실을 앞세운 제목 등).
  보도자료를 그대로 받아쓴 동일 제목 기사가 판단 기준이다.
  이 기준은 언론 보도 구역 제목 오른쪽에 안내 문구(`.ieg-note`)로 표시한다.
  소식지 구역은 같은 자리에 '월간 주요 소식'을 표시한다.
- 뉴스와이어(자사 보도자료 배포)는 싣지 않는다. 언론사 기사만 싣는다.
- 포털·기관·자사 재게시본은 싣지 않는다. 단 원문이 목록에 없어 그 재게시본이 해당 사안의
  유일한 기록이면 싣고 `note`에 출처를 적는다(예: `note:'뉴스와이어 재전송'`).
  재게시 매체는 `RANK` 맨 끝에 두어 원문 뒤에 오게 한다.
- 위 규칙에 걸리지 않는 기사는 빠짐없이 싣는다.
- 사용자가 뺀 기사(다시 넣지 않는다): 캐드앤그래픽스 2026-08-07 '아이지, 2026년 제2차 혁신 프리미어 1000 선정… 글로벌 테크에듀 기업 도약'(2026-10-15).
- 개별 기사 URL이 확인되지 않은 건은 싣지 않는다. 매체 홈/목록 페이지로는 연결하지 않는다.
- 브랜드 색: 대표 #FF0000, 보조 #FFB300, 무채색 #333333. **세 색이 조화로운 포인트로 함께 들어간다**(아래 '색의 역할').

## 디자인 원칙

- **디자인 시스템은 `Update/0.txt`(Apple 웹 디자인 언어)다.** 새 화면이나 요소는 이 문서를 따른다.
  - 면: 흰색(`--canvas`)과 연회색(`--parch` #F5F5F7)을 쓴다. 짙은 면은 쓰지 않는다.
    색이 바뀌는 것 자체가 구분선이다.
    배경은 아래 '점 물결' 하나만 쓴다. 그 밖의 배경 장식(그라데이션·무늬·빛 번짐·종이 질감)은 넣지 않는다. 내용은 모두 흰 패널 위에 놓는다.
  - 글자: 모든 글자는 `--ink`(#333333), 보조는 `--muted`. 본문 17px/1.47. 제목은 굵기 600에 자간을 조인다.
    굵기는 400/600(필요하면 700)만 쓰고 500·800·900은 쓰지 않는다(제호만 예외로 800).
    글꼴은 `-apple-system`(맥: SF Pro) → Pretendard(그 밖) 순서.
  - **색의 역할**(디자인 시스템의 '강조색 하나' 규칙 대신 브랜드 세 색을 쓴다):
    - #333333 `--ink`: 모든 글자, 제호의 NEWS, 지금 페이지 바로가기·페이지 번호의 채운 알약.
    - #FF0000 `--red`: 주 포인트. 제호의 IEG, 언론사 이름, 더보기 알약(빨강으로 채움, hover 시 테두리만), 제목 hover.
    - #FFB300 `--amber`: 보조 포인트. 기사 hover 면(`--amber-soft`), 글자 선택색.
    - 포인트는 작게, 여러 곳에 고르게 둔다. 넓은 면을 빨강·노랑으로 칠하지 않는다.
    - **색색깔 선은 쓰지 않는다**(세 색을 이은 띠, 빨강→노랑 막대, 그라데이션 선 등). 선은 머리카락 선(`--hair`)이나 한 가지 색만 쓴다.
  - 그림자는 사진(소식지 지면, 확대 보기)에만 하나 쓴다: `3px 5px 30px rgba(0,0,0,.22)`. 카드·버튼·글자에는 그림자를 쓰지 않는다.
  - 더보기 버튼은 넉넉하게: 최소 188×50px, 내용과 30px 띄운다.
- 모양: 버튼은 알약(999px), 목록 썸네일 8px, 언론 보도 패널 18px, 항목 hover 면 18px, 사진 위 조작 버튼은 44px 원(`.ieg-circle`).
  - 누르면 `scale(0.95)`로 살짝 줄어든다. 머리 막대는 반투명 흰 막(blur)이다.
- 요청받지 않은 텍스트·라벨·숫자(부제, 일련번호, 수량, 요약 등)를 넣지 않는다.
- 글자를 키워서 강조하지 않는다. 예외로 **제호(IEG NEWS)는 눈에 띄게** 둔다: 굵기 800, 데스크톱 44px(최대 52px),
  화면에서 가장 큰 글자다. 구역 제목(소식지·언론 보도)은 그보다 작게(최대 28px) 둔다.
- **커서를 따라다니는 요소는 넣지 않는다.** 배경 점이 커서 근처에서 밀려나는 반응은 괜찮다(사용자가 요청한 인터랙티브).
- **배경: 점으로 된 물결**(`startDotWave`, 캔버스 `.ieg-fx`, 화면에 고정, 패널 뒤 연회색 면에서만 보인다).
  - 26px(휴대폰 22px) 간격의 점이 **확실히 파도친다**: 큰 너울(파장 약 750px)이 사선으로 휘며 왼쪽 위에서 오른쪽 아래로
    밀려오고(약 6초에 한 파장) 작은 물결이 엇갈려 겹친다. 점은 물 입자처럼 원을 그리며 ±14~20px 움직인다.
    마루일수록 점이 크고 진하다(세제곱으로 마루만 도드라져 파도 줄기가 또렷하다).
  - 커서 반경 150px 안의 점은 물이 갈라지듯 밀려나며 빨강(#FF0000)으로 물든다.
  - 패널·메뉴·버튼·링크가 아닌 빈 곳을 누르면 그 자리에서 노랑(#FFB300) 물결이 1.8초 동안 퍼진다(최대 5개).
  - 탭이 가려지면 멈춘다. '동작 줄이기' 설정이면 멈춘 점만 그리고 커서·클릭에 반응하지 않는다.
  - 페이지 바탕은 연회색(`--parch`), 면(`.ieg-tile`)은 투명이라 점이 비친다.
- **게임(놀이 모드)은 넣지 않는다.** 써 보고 없애기로 했다. 예외는 사용자가 따로 요청한 아래 제호 변신 장면뿐이다.
- **제호 변신 장면(`playIegFinale`, 약 5.7초. 다 맞물린 뒤 빛이 한 번 스치고 곧 제호 자리로 간다 — 오래 머무는 것은 사용자가 줄였다)은 두 경우에만 나온다**(사용자 요청, 2026-10-15): **홈에 처음 들어올 때**(새로 불러올 때 한 번)와
  **머리 막대의 제호를 누를 때**(다른 페이지면 홈으로 간 뒤, 이미 홈이면 그 자리에서). 떠다니는 것을 잡아서 나오던 방식은 없앴다.
  호출은 `startDotWave(...).play(intro)`. `intro`(첫 진입)면 패널이 처음부터 숨은 빈 무대에서 시작한다(`html.ieg-pre`로 미리 숨김).
  - 장면: **패널·머리 막대가 투명하게 사라져 깔끔한 전체화면 빈 무대**가 되고(문처럼 열리기·IEG가 가운데로 날아오기는 없다, 사용자 요청)
    → **판금 조각 변신**(사용자가 고른 방식): **'IEG NEWS' 한 줄 전체**(NEWS 포함, 사용자 요청)를 글자마다 금속 판 몇 장으로 자르고(잠기면 IEG는 빨강, NEWS는 #333333),
    판 앞면은 실제 글자 모양 그림이다(두께는 얇은 겹을 촘촘히 쌓아 그린다). 판들이 각자 제 글자 자리로
    날아가, 경첩 쪽으로 160도 접힌 채 조금 뒤에서 기다린다(**가운데에 뭉친 덩어리는 어색하다는 사용자 의견으로 두지 않는다**)
    → I·E·G 순서로(글자 안에서는 가운데 조각부터) 각 판이 톡 풀려 앞으로 나오고, 글자 가운데를 향한 모서리를
    경첩 삼아 철컥 펴지며(살짝 지나쳤다 제자리) 쾅 눌려 빨갛게 잠김(판마다 경첩 자리에 작은 불꽃·울림).
    강철 판에는 글자 테두리를 따라 모서리 빛(베벨)이 있고, 빛을 정면으로 받는 각도에서 번쩍인다(둘 다 쾅까지 사라진다) → 쾅 → 판 앞면이 글자 모양 그대로라 같은 자리에 매끈한 입체 로고가
    이음 없이 나타난다(용접 단계 없음). (작은 정육면체 수천 개로 하던 판은 버벅여서 바꿨다.) → 로고는 정면을 지킨 채
    (**좌우로 돌아보는 시점 이동은 어색하다는 사용자 의견으로 뺐다**. **판금 단계도 대각선으로 꺾이는 시점 없이 처음부터 정면만 본다**(`camAt`이 늘 0), **로고 밑 바닥 그림자는 넣지 않는다**, 둘 다 사용자 요청 2026-10-15) NEWS가 한 글자씩 일어서고, 앞면 빛줄기가 IEG부터 NEWS까지 한 줄로 이어 샤악 지나간 뒤
    펼쳐짐 → 머리 막대의 제호 자리로 날아가 정확히 겹쳐 앉는다. **내려앉을 때는 테·물결 같은 효과를 주지 않는다**(사용자 요청)
    → 머리 막대가 먼저, 이어 패널이 돌아온다. 누르거나 Esc로 건너뛴다. 끝나면 패널 등에 준 스타일을 모두 지운다.
  - 바로가기 #으로 홈에 돌아올 때는 나오지 않는다. '동작 줄이기' 설정이면 나오지 않는다.
  - (예전 인트로 — 점이 IEG NEWS로 모이는 것, 원형 물결 — 은 되살리지 않는다.)
- **배경을 떠다니는 이스터에그는 두지 않는다**(사용자 요청, 2026-10-15). 빨간 빛 점 → 우주선 → 로봇 → IEG 글자 → 세포 → 별빛까지 써 보고
  사용자가 기능 자체를 없애기로 했다. 되살리지 않는다. 빈 배경을 누르면 노란 물결만 퍼진다.
  그 밖에 스크롤해서 들어오는 항목이 떠오르는 것과, 사용자가 일으키는 반응은 괜찮다.
- **배경을 두 번·여러 번 눌러도 글자가 선택돼 칠해지지 않는다**: `body`는 `user-select: none`, 패널 안(`.ieg-panel`)만 `text`.
  배경에서 누르기(mousedown)는 기본 동작을 막아 선택이 시작되지 않게 한다.
- 소식지 지면에 커서를 올리면 흰 빛줄기가 한 번 스친다(`iegShine`). 노란 테두리·둘레 빛은 넣지 않는다.
- 헤드리스 시험(캔버스 애니메이션): 가상 시간에서는 애니메이션 프레임이 거의 돌지 않으므로 시험 사본에서 requestAnimationFrame을
    16ms setTimeout으로 바꾸고, 찍기 직전에 캔버스를 이미지(toDataURL)로 덮어 찍는다.
    매 프레임 스타일을 바꾸는 장면(제호 변신 장면)은 찍기 직전에 프레임 예약을 멈춰야 찍힌다(계속 바뀌면 처음 화면이 찍힌다).
    또 --screenshot은 찍기 직전에 창 크기를 다시 맞추므로 resize에 반응하는 코드는 시험 사본에서 끄거나,
    같은 폭의 iframe 안에서 돌려 찍는다.
- hover 강조는 선이 아니라 **항목 전체**에 준다(언론 보도 줄: 옅은 노랑 면 + 제목 빨강 + 썸네일 살짝 확대).
- 같은 역할의 요소는 같은 모양을 쓴다(`.ieg-pill`, `.ieg-link`, `.ieg-circle`, `.ieg-card`). 두 구역 바로가기는 항상 같은 크기.
- 고객이 보기 편한 것이 우선이다: 첫 화면에서 최신 소식지 표지와 최근 기사가 바로 보이고, 긴 내용은 더보기·확대 보기로 연다.
- **스크롤 애니메이션**(`animation-timeline: view()/scroll()`, 지원 안 되는 브라우저는 효과 없이 그대로):
  - **머리 막대는 스크롤해도 고정**이다: 늘 화면 위에 붙어 있고 높이·제호 크기도 바뀌지 않는다
    (막대가 얇아지거나 로고가 작아지는 효과는 하지 않기로 했다).
  - 구역 제목은 왼쪽에서, 안내 문구는 오른쪽에서 들어온다.
  - 소식지 지면: 작고 아래에 있다가 제 크기로 떠오른다(`entry 0%~45%` — 첫 화면에 걸친 지면이 반쯤 흐린 채로 남지 않게).
  - 목록 줄은 아래에서 떠오른다(`entry` 범위라 화면 안에 다 들어온 줄은 완성된 모습).
  - 썸네일 사진: 1.14배로 키워 두고 스크롤보다 느리게 ±6% 움직인다(깊이감).
    사진 상자는 `overflow: clip`이어야 한다(hidden이면 스크롤 상자가 되어 페이지 스크롤에 반응하지 못한다).
    clip이면 상자가 사진 비율대로 늘어나므로 `min-height: 0` + 사진 `position: absolute`로 16:10을 고정한다.
  - 더보기·페이지 번호는 아래에서 떠오른다.
  - 첫 화면에 보이는 요소는 처음부터 완성된 모습이어야 한다(반쯤 흐린 상태로 뜨면 안 된다).
- 움직임은 은은하게 하고, `prefers-reduced-motion`이면 모두 끈다.
- hover의 `transform`과 등장 효과가 겹치지 않도록 등장 효과는 `translate`·`scale` 속성만 쓴다.
- 이전에 써 보고 바꾼 배경(되살리지 않는다): 흐르는 물결선, 여백 회로 기판, 어두운 기판 위 종이 지면,
  오로라 + 점 격자, 천체도·별 흐름, 빛의 입자.
## 날짜 게이지

- **오른쪽 날짜 게이지(연·월 눈금)와 화면 위쪽 진행 막대는 두지 않는다**(사용자 요청, 2026-10-15: 모바일에서 겹쳐 써 보고 없앴다). 되살리지 않는다.

## 화면 확인 방법

- 로컬에 Chrome이 있으므로 헤드리스로 실제 화면을 찍어 확인한다
  (`chrome --headless=new --screenshot --window-size=… --virtual-time-budget=20000 file:///…`).
- 헤드리스 Chrome은 창 폭을 최소 약 500px로 강제한다. 휴대폰 폭(390px)은 그 폭의 iframe 안에
  페이지를 띄워서 확인해야 한다. 그냥 창 폭을 줄이면 잘린 것처럼 보이지만 실제 버그가 아니다.
- 헤드리스 `--screenshot`은 스크롤된 화면을 제대로 못 찍는다(위가 비고 밀려 나옴). 스크롤 상태는
  본문 래퍼에 `transform: translateY(-Npx)`를 걸어 흉내 내고, 이때는 전환·스크롤 등장 효과를 꺼야 한다.
- 스크롤 애니메이션의 중간 모습은 iframe 안의 페이지가 스스로 `scrollTo`하게 하고 바깥(harness)을 찍어서 본다
  (file://에서는 바깥이 iframe을 스크롤할 수 없다. `--dump-dom`의 가상 시간에서는 스크롤 뒤 애니메이션 값이 갱신되지 않는다).
- 헤드리스의 가상 시간에서는 부드러운 스크롤이 진행되지 않는다. 클릭으로 이동하는 동작은
  `--force-prefers-reduced-motion`(즉시 스크롤)으로 돌리고, 결과를 DOM 속성에 적어 `--dump-dom`으로 꺼내 확인한다.
